# 统一语义工程

本目录用于维护 MaxiEAM、HD_SAAS、XNY_SAAS 等数据源的统一语义资产。

当前项目包含一个用于高质量设备语义候选生成、上下文校验、审核和发布的本地系统：

- 前端：React + TypeScript + Vite + Ant Design
- 后端：FastAPI
- 工作流存储：SQLite
- 分析查询：DuckDB 1.5.5
- 开发调试：`start_dev.ps1` 启动 FastAPI 热更新和 Vite HMR

## 本地启动

```powershell
cd semantic-engineering
.\start_dev.ps1
```

前端默认访问 `http://127.0.0.1:5173`，通过 Vite 代理访问本地 FastAPI 的 `/api` 接口。

首页“继续审核”进入固定的 `high-quality-300-v1` 样本范围。样本按电厂和分类分层抽取，审核只记录在本地 SQLite；完成 300 条样本后，再生成回放评估集和术语规则候选。

后端依赖安装和单独启动方式见 `backend/README.md`。本地数据库、原始快照、候选 CSV 和依赖目录均通过 `.gitignore` 排除；运行系统需要使用本地数据快照初始化工作流库。

## 边界

- 源库和源表只读；不在这里直接修改 MaxiEAM 或 DM8 源数据。
- 先确认表粒度、稳定身份键和来源证据，再建立跨源映射。
- 保留原始字段名、原始值、规范化值和映射依据。
- 设备身份、设备描述、位置、分类、属性和显式关系优先纳入统一语义范围。
- 生成结果必须可追溯、可校验、可复核；未经批准不进入正式结果层。
- 不引入本体、知识图谱、TTL 或本体治理设计。

## 建议结构

- `inventory/`：源表、字段、注释、主键和关系盘点
- `contracts/`：统一实体、字段和身份键契约
- `mappings/`：跨源字段与术语映射
- `rules/`：确定性规范化和术语规则
- `reports/`：只读盘点、差异和回归报告

## 当前数据源

- MaxiEAM：设备及其业务上下文
- DM8 `HD_SAAS`：GRP 元数据与业务对象
- DM8 `XNY_SAAS`：GRP 元数据与业务对象

## 变更原则

任何统一语义结论都要记录来源 schema、表、字段、快照时间和证据；发现冲突时保留冲突并进入复核，不静默覆盖。
